kaBluey — Privacy Policy

Publisher: Brendon Davis  |  Application: kaBluey (time-tracking tray application for Windows)  |  Last updated: 2026-06-17

Summary: kaBluey is a local-first time-tracking tool. All data you enter is stored only on your own device. kaBluey has no servers, collects no analytics or telemetry, shows no ads, and does not sell or share your data. The only external connection it makes is to Microsoft Graph (Outlook / Microsoft 365), and only when you explicitly enable and sign in to that feature.

1. Information collected and stored locally

The following is stored only in local files on your device (by default in your Documents\kaBluey folder) and is never transmitted anywhere by kaBluey itself:

  • Email address and role type — entered once in Settings; used to label your time entries and, if you enable Microsoft 365 sync, to identify which Microsoft account to authenticate as.
  • Time log entries — start/stop times, job or ticket names, labour-type category, and free-text notes for each tracked time block.
  • Job and task lists — names of jobs and tickets you have worked on, including any imported from Outlook Tasks if you enable that feature.
  • Application settings — your configured schedule, sound, calendar, and sync preferences (stored in kabluey.ini).
  • Window size and position — saved so the app reopens where you left it.

This data is never read by, or transmitted to, blueAPACHE or any other party. Every one of these files is plain text and can be inspected, edited, backed up, or deleted by you at any time.

2. Microsoft 365 / Outlook integration (optional)

kaBluey can optionally sync with your Microsoft 365 mailbox using the Microsoft Graph API. This feature is off until you turn it on and sign in. It uses the following OAuth permissions, requested only when the corresponding feature is enabled:

  • Calendars.ReadWrite — to create calendar events from your time entries, and (if you enable the calendar preview feature) to read your calendar so you can tick events into your time log.
  • Tasks.ReadWrite — requested only if you enable Outlook Tasks sync — to read and create tasks tagged with your configured category.

Authentication uses Microsoft's standard device-code sign-in flow. Your Microsoft 365 credentials are never seen, stored, or processed by kaBluey — only Microsoft's own sign-in page handles your password. The resulting access token is cached locally using your operating system's secure credential store (Windows Credential Manager) so you do not need to sign in every time.

All calendar events and tasks created by this sync are created directly in your own mailbox, under your own organisation's Microsoft 365 tenant. blueAPACHE has no server in this flow and never receives a copy of your calendar, tasks, or any other mailbox content.

To disconnect kaBluey from Microsoft 365, open Windows Credential Manager, find the entry named kaBluey-m365, and delete it. You can also revoke access entirely from myapps.microsoft.com → My Apps → kaBluey → Remove access.

3. Data we do not collect

kaBluey does not collect or transmit:

  • Usage analytics, telemetry, or crash reports
  • Advertising identifiers, or any data for advertising purposes
  • Location data
  • Contacts, photos, or files outside its own data folder
  • Any data to blueAPACHE's own servers — blueAPACHE does not operate any server that kaBluey communicates with

4. Data retention and deletion

  • Daily log files are kept locally for a configurable retention period (default 14 days) and deleted automatically after that period.
  • Uninstalling kaBluey removes the application but does not automatically delete your personal data. To remove all data, delete the Documents\kaBluey folder manually after uninstalling.
  • Disconnecting Microsoft 365 sync (or revoking access at myapps.microsoft.com) removes kaBluey's ability to access your mailbox. Any events or tasks already created remain in your mailbox under your organisation's normal retention rules, the same as anything else created in Outlook.

5. Device security checks (Full mode)

On enterprise-managed devices, kaBluey performs a local check of your device's security posture (Entra ID join status on Windows, via dsregcmd) to decide whether to enable additional features ("Full mode"). These checks run entirely on your device, read only local system state, and are never transmitted anywhere.

6. Children's privacy

kaBluey is a workplace productivity tool intended for adult employees and is not directed at, or knowingly used by, children under 13.

7. Open source

kaBluey's source code is publicly available for review at github.com/bABrendonDavis/kaBluey. You or your organisation's IT or security team are welcome to audit the source to verify the practices described in this policy.

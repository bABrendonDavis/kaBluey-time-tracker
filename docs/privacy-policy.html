kaBluey — Privacy Policy

Publisher: Brendon Davis  |  Application: kaBluey (time-tracking tray application for Windows and macOS)  |  Last updated: 2026-11-05

Summary: kaBluey is a local-first time-tracking tool. All data you enter is stored only on your own device. kaBluey has no servers, collects no analytics or telemetry, shows no ads, and does not sell or share your data. It connects to the internet only for the features listed in section 3, and only when they are in use.

1. Information collected and stored locally

The following is stored only in local files on your device (by default in your Documents\kaBluey folder) and is never transmitted anywhere by kaBluey itself:

  • Email address and role type — entered once in Settings; used to label your time entries and, if you enable Microsoft 365 sync, to identify which Microsoft account to authenticate as.
  • Time log entries — start/stop times, job or ticket names, labour-type category, and free-text notes for each tracked time block.
  • Job and task lists — names of jobs and tickets you have worked on, including any imported from Outlook Tasks if you enable that feature.
  • Application settings — your configured schedule, sound, calendar, and sync preferences (stored in kabluey.ini).
  • Window size and position — saved so the app reopens where you left it.

This data is never read by, or transmitted to, Brendon Davis or any other party. Every one of these files is plain text and can be inspected, edited, backed up, or deleted by you at any time.

2. Microsoft 365 / Outlook integration (optional)

kaBluey can optionally sync with your Microsoft 365 mailbox using the Microsoft Graph API. This feature is off until you turn it on and sign in. It uses the following OAuth permissions, requested only when the corresponding feature is enabled:

  • Calendars.ReadWrite — to create calendar events from your time entries, and (if you enable the calendar preview feature) to read your calendar so you can tick events into your time log.
  • Tasks.ReadWrite — requested only if you enable Outlook Tasks sync — to read and create tasks tagged with your configured category.

Authentication uses Microsoft's standard device-code sign-in flow. Your Microsoft 365 credentials are never seen, stored, or processed by kaBluey — only Microsoft's own sign-in page handles your password. The resulting access token is cached locally with per-user operating-system protection so you do not need to sign in every time: on Windows it is stored as a DPAPI-encrypted file bound to your Windows user account (optionally reinforced with a secret in Windows Credential Manager via the "Enhanced security" setting), and on macOS in the system Keychain. The token never leaves your device.

All calendar events and tasks created by this sync are created directly in your own mailbox, under your own organisation's Microsoft 365 tenant. The developer has no server in this flow and never receives a copy of your calendar, tasks, or any other mailbox content.

To disconnect kaBluey from Microsoft 365, delete the encrypted token file from your kaBluey data folder (or use Settings → Microsoft 365 → Disconnect). You can also revoke access entirely from myapps.microsoft.com → My Apps → kaBluey → Remove access.

3. What kaBluey sends over the internet

kaBluey connects to the internet only for these features, and only when they are in use:

  • Microsoft 365 (login.microsoftonline.com, graph.microsoft.com) — when you connect and sync.
  • Your organisation's Kablammo server — Full mode only, when your administrator sets kablammo_fqdn and you connect.
  • GitHub (api.github.com) — only if you enable the update check (update_check_enabled, off by default) or start kaBluey with --check-updates.
  • kaBluey's labour-type list (kabluey.blob.core.windows.net) — downloaded after a Microsoft 365 sync when Kablammo is not in use.
  • An INI file URL set by your administrator (ini_download_url) — at startup, if configured.

None of these requests send your time logs except to Microsoft 365 or Kablammo. As with any web request, the server sees your IP address. There is no telemetry, analytics or advertising.

4. Data we do not collect

kaBluey does not collect or transmit:

  • Usage analytics, telemetry, or crash reports
  • Advertising identifiers, or any data for advertising purposes
  • Location data
  • Contacts, photos, or files outside its own data folder
  • Any data to any developer-operated server — kaBluey does not communicate with any server operated by its developer

5. Data retention and deletion

  • Daily log files are kept locally for a configurable retention period (default 14 days) and deleted automatically after that period.
  • Uninstalling kaBluey removes the application but does not automatically delete your personal data. To remove all data, delete the Documents\kaBluey folder manually after uninstalling.
  • Disconnecting Microsoft 365 sync (or revoking access at myapps.microsoft.com) removes kaBluey's ability to access your mailbox. Any events or tasks already created remain in your mailbox under your organisation's normal retention rules, the same as anything else created in Outlook.

6. Device security checks (Full mode)

On enterprise-managed devices, kaBluey performs a local check of your device's security posture (Entra ID join status on Windows, via dsregcmd; MDM enrolment on macOS) to decide whether to enable additional features ("Full mode"). These checks run entirely on your device, read only local system state, and are never transmitted anywhere.

7. Children's privacy

kaBluey is a workplace productivity tool intended for adult employees and is not directed at, or knowingly used by, children under 13.

8. Open source

kaBluey's source code is publicly available for review at github.com/bABrendonDavis/kaBluey-time-tracker, where each release and its signed checksums are published. You or your organisation's IT or security team are welcome to review the release and verify the practices described in this policy.

If this policy changes, the updated version will be published at this URL and noted in the project's changelog, with the "Last updated" date above revised accordingly.
